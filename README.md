# 轻课表 · BIT CourseLite

这是一个独立的北京理工大学课表 App：在学校官方网页完成登录后，读取所选学期的课表，保存在手机上，方便按周查看。它不依赖 Excel，也没有把某个学年或学期写死。

默认开启“跟随学校当前学期”。**每次同步都会重新向学校查询当前学期，因此进入新学期后可以继续导入新课表。** 如果学校返回的当前学期尚未更新，或者需要查看往期课表，可以在设置中关闭此选项，再填写指定学期，例如 `2026-2027-1`。这只是格式示例；支持连续年份以及编号 1、2、3 的学期，具体有没有课程由学校返回的数据决定。

适用于 Android 8.0 及以上。正式版包名是 `cn.local.bitcourse`，使用独立签名，可与 BIT101 同时安装，不会覆盖或替换 BIT101。

1.0.3 按每周的实际安排合并同一课程的连续节次：课程名、教师、教室、校区和星期一致时，合并该周相邻的节次。不同周次仍分别计算，例如前两节在第 1–11 周、第三节仅在第 1–10 周，会显示为第 1–10 周连续三节、第 11 周两节。周课表、课程列表和点击详情使用相同结果；原始课表缓存保留，覆盖安装后已有课表即可使用此规则，无需重新导入。无法区分来源的重叠记录继续保留，以免把不同课程误删。

1.0.2 的首页只保留一行周次工具栏和课表，移除了大标题与常驻状态卡。七天等宽显示，全天节次按剩余屏幕高度排布；普通竖屏可一屏看到周一至周日及最后一节课，极矮窗口或节次较多时才使用纵向滚动。课程名过长时可点击查看完整信息，同日重叠课程会显示数量并提供选择列表；日期设置、课程列表和同步详情移入设置。

手动同步进入提取阶段后，会显示醒目的导入提示框，按真实流程提示确定学期、提取课程、读取校历和保存到手机；支持取消导入。完成后提示框关闭，回到完整课表。重要结果以短暂提示显示，不占用固定课表空间；打开 App 时的自动同步仅在工具栏显示小进度指示，可点击取消。

1.0.1 修正了内嵌浏览器的布局参数：WebView 在创建时明确使用 `MATCH_PARENT`，避免默认 `WRAP_CONTENT` 让学校页面的百分比高度计算为 0。使用原签名发布的 1.0.1 可以直接覆盖安装到 1.0.0，无需卸载。

第一次使用：

1. 安装 APK，点击“登录学校，导入课表”。在学校网页中完成账号、验证码等验证。
2. 校园网络可先使用“校园直连”；校外连接失败时，在登录页或设置中切换“校外访问（WebVPN）”。两种访问方式都使用学校网页。
3. 登录完成后，App 自动读取学期、课表及校历。无需手动复制 Cookie 或接口返回内容。
4. 同步成功后，可以切换周数、查看周课表或课程列表；点击课程可查看教室、教师、校区和周次。
5. 如果没有可靠的校历日期，仍可按周浏览课程。点击“设置第 1 周日期”，选择该学期第 1 周的星期一。手动日期按学期分别保存，后续同步会保留你的选择。

首次成功同步后，默认在以后打开 App 时尝试同步；也可以随时点击同步按钮。设置中可以关闭“打开 App 时自动同步”。**没有后台定时任务，也不会在 App 关闭后持续监测学校课表。** 学校登录过期时，需要再次进入学校网页登录。

不同学期的课表分别缓存。关闭“跟随学校当前学期”并选择一个已保存的学期，可以离线查看对应课表。网络错误、登录失败或无法识别的接口数据不会被当作空课表覆盖缓存；学校明确返回合法的空课程列表时，会保存为“本学期暂无已排课程”。退出学校登录后，本地课表仍然保留。

周次以接口的中文周次字段为优先来源；缺少可用中文周次时才使用位图周次，并显示提示。只有各条记录的周次关系一致时，才自动计算校历偏移。这个偏移由当次数据推断，不固定为 3 周。不能可靠判断时，需要手动确认第 1 周日期。当前界面和解析范围为第 1 至 60 周、第 1 至 30 节。

源码构建：

- 使用 JDK 17、Android SDK Platform 36，并配置 `JAVA_HOME` 及 Android SDK 路径。可以通过 Android Studio 配置 SDK，也可以使用本机的 `local.properties`，例如 `sdk.dir=D:/Android/Sdk`；该示例路径需要替换为实际路径。
- 使用项目自带的 Gradle Wrapper。当前工程使用 Gradle 8.14.5、Android Gradle Plugin 8.13.2、Kotlin 2.4.10。首次构建需要获取相应 SDK 和依赖；已经缓存的依赖可以复用。
- 在项目根目录执行以下 PowerShell 命令，运行 JVM 单元测试并生成调试 APK。调试版不需要正式版私钥，包名带 `.debug` 后缀。

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug
```

调试 APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。在 macOS 或 Linux 上，使用 `./gradlew` 执行相同任务。

调试源码中的 `ImportPreviewActivity` 用于离线检查导入提示框，可通过 `phase` 参数查看 `READING_TERM`、`READING_COURSES`、`READING_CALENDAR`、`SAVING` 模拟阶段。它不请求学校、不读写课表，仅使用正式界面的同一提示框组件；正式版不包含该 Activity 和入口。

正式版需要你自己的 PKCS12 签名密钥。将密钥及签名配置放在源码目录之外，例如 `D:/PrivateKeys/course-lite/`。可使用 JDK 的 `keytool` 创建密钥；密码通过交互提示输入，不写在命令行中：

```powershell
keytool -genkeypair -alias course-lite -keyalg RSA -keysize 3072 -validity 10000 -storetype PKCS12 -keystore D:/PrivateKeys/course-lite/course-lite-release.p12
```

在同一外部目录中准备 `signing.properties`，填写自己的值：

```properties
storeFile=course-lite-release.p12
storePassword=YOUR_STORE_PASSWORD
keyAlias=course-lite
keyPassword=YOUR_KEY_PASSWORD
```

`storeFile` 相对于此配置文件所在目录解析。正式版构建命令为：

```powershell
.\gradlew.bat :app:assembleRelease "-PcourseLiteSigningProperties=D:/PrivateKeys/course-lite/signing.properties"
```

正式版 APK 位于 `app/build/outputs/apk/release/app-release.apk`。未提供有效签名配置时，正式版构建会失败；可先构建调试版。后续发布升级版本时，应继续使用同一签名密钥并提升版本号。**私钥、密码和 `signing.properties` 不应提交到代码仓库或放进源码分发包；本项目源码不提供正式版私钥。**

当前限制：

- 尚未使用真实学校账号完成手机上的端到端登录和导入验证。解析及构建检查不能替代这项验证，也不能保证所有账号、验证码流程或网络环境都能成功登录。
- 本 App 使用学校教学中心的课表及校历接口。学校调整接口、登录流程或权限后，可能需要更新 App；任意合法学期格式不代表学校一定提供该学期的数据。
- “跟随学校当前学期”采用学校接口返回值，不根据手机日期猜测学期；学校返回旧学期时，应暂时手动指定需要的学期。
- 研究生与其他培养类型可能使用不同的校历口径。请核对中文周次和第 1 周日期；无法确认时使用手动日期。课表以学校正式安排为准。
- 本项目只处理课表，没有考试安排、成绩、消息推送或 Excel 导入功能。

网页登录会话与本地数据的具体处理方式见 [PRIVACY.md](PRIVACY.md)。
